# Asset curation and minimal zine presentation

User goal: inventory personal assets, consolidate obvious repetition and reorganize presentation, learning the visual language of LiamGvchi/gc-minimal-zine-poster. Four interests retain equal standing. Root hosting and retired Doc/CV URLs remain unchanged.

Reference studied: README, SKILL and style/analysis/quality references, plus the actual night-door and yellow-step samples (686×1144). Observed: broad paper fields, small offset focal cluster, sparse editorial text, a strong single chromatic carrier, flat printed treatment. Proposed website adaptation: readable text and usable navigation take precedence over literal poster microtype or mandatory vertical aspect ratio. No reference imagery, wording or exact composition is copied. This is a website interpretation, not invocation of the poster generation workflow.

Selected approach: editorial index. Alternatives considered were a poster wall (harder to scan and maintain) and one long narrative page (poor for a growing technical collection). Homepage: quiet personal cover, four equal section links, selected content index and a compact personal colophon. Work: actual project diagrams as modest printed specimens. Research: one publication plus connected reading paths. Writing: one canonical entry per subject, full-text search, type/topic filters. Life: original photography as a separate journal, with original colors preserved in the full gallery. About and archive remain secondary.

Content decisions: merge identical Flow Matching article/note; merge CUDA resource stub into the complete CUDA note; consolidate duplicate C++ container notes and mixed-topic NN notes; combine Go/Gin/Auth/DB/Redis stubs into one resource note; keep materially different drafts and bibliography sources unlisted rather than silently deleting their unique content. Preserve historical records and use canonical redirects for editions that share the exact same body. Consolidate exact-byte media duplicates and rewrite all retained references before removal. Keep original source and Git history; do not touch the external Obsidian vault or other GitHub repositories.

Deliverables: reusable asset inventory JSON/Markdown, explicit merge provenance, final information architecture, coherent paper/ink/cobalt design across all page types, responsive and reduced-motion behavior, functional search/gallery/reading controls, automated link/content/accessibility checks, visual review, and verified root deployment.
